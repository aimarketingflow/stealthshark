StealthShark

Cross-Platform Concept Paper: Windows & Linux
Version 3.0 • August 2026 • AI Marketing Flow

1. Executive Summary

StealthShark v3.0 is currently a native Swift/SwiftUI macOS application (~2,700 lines, 3.3 MB binary) that provides real-time multi-interface network monitoring, tshark-based packet capture, pattern recognition, and session management.

This concept paper outlines how to port StealthShark to Windows and Linux while preserving the same architecture, features, and user experience. Two viable approaches are presented: a cross-platform GUI framework approach and a native per-platform approach.

Goal: Enable the same StealthShark monitoring experience on Windows 10/11 and major Linux distributions (Ubuntu, Fedora, Arch) with minimal code divergence from the macOS version.

2. Current macOS Architecture

Understanding the macOS version is essential before porting. Here is the component map:

Platform-Specific Code (Must Be Ported)

Component macOS API What It Does Portability
Interface Discovery getifaddrs() Enumerates network interfaces + addresses POSIX Available on Linux; Windows uses GetAdaptersAddresses
Interface Stats netstat -ib (shell) Bytes/packets per interface Varies Linux: /proc/net/dev; Windows: Get-NetAdapterStatistics
Process Launch Foundation.Process() Spawns tshark subprocesses Easy All platforms have process spawn APIs
UI Framework SwiftUI All views, navigation, controls Rewrite SwiftUI is macOS-only; must replace entirely
Menu Bar MenuBarExtra System tray presence Varies Windows: system tray; Linux: app indicator / tray icon
Data Directory ~/Library/Application Support/ Config + captures + sessions Easy Windows: %APPDATA%; Linux: ~/.local/share/
tshark Path /opt/homebrew/bin/tshark Packet capture binary Easy Windows: C:\Program Files\Wireshark\tshark.exe; Linux: /usr/bin/tshark

Platform-Independent Code (Portable As-Is)

The following logic is pure business logic and can be ported with minimal changes regardless of approach:

  • PatternRecognitionEngine — All anomaly detection math (spike detection, ratios, thresholds)
  • SessionManager — JSON serialization/deserialization of preferences and state
  • DebugLog — Thread-safe logging with level filtering
  • DataModels — All data structures (NetworkInterface, CaptureStats, PatternAlert)
  • Auto-restart logic — Duration/size threshold checking

3. Approach A: Cross-Platform GUI Framework

Use a single codebase with a cross-platform UI toolkit. This is the recommended approach for teams that want to maintain one codebase.

Option A1: Tauri + TypeScript

Recommended

  • Rust backend + web frontend (React/Svelte/Vue)
  • ~5 MB app bundle (much smaller than Electron)
  • Native system tray on all platforms
  • Rust has excellent getifaddrs / process APIs
  • WebView2 (Win), WebKit (macOS/Linux)

Effort: ~2-3 weeks for a senior dev

Option A2: Electron + TypeScript

Viable

  • Proven cross-platform desktop framework
  • Large ecosystem, easy to find developers
  • Built-in system tray, auto-update, packaging
  • Node.js child_process for tshark
  • Downside: ~150 MB bundle, higher memory usage

Effort: ~2-3 weeks for a senior dev

Option A3: Python + Qt6 (PySide6)

Familiar

  • StealthShark v2.x was Python/PyQt6 — code exists
  • Cross-platform with native look on each OS
  • System tray via QSystemTrayIcon
  • subprocess for tshark management
  • Bundle with PyInstaller or Nuitka (~50-80 MB)

Effort: ~1-2 weeks (existing code as base)

Option A4: Flutter Desktop

Viable

  • Dart language, Material Design widgets
  • Single codebase for macOS, Windows, Linux
  • Growing desktop support (stable since 2022)
  • FFI for native calls, Process.run for tshark
  • Smaller community for desktop vs. mobile

Effort: ~3-4 weeks for a senior dev

Recommendation: Tauri + React/TypeScript

Why Tauri? It gives you the smallest bundle size (~5 MB vs Electron's 150 MB), near-native performance via Rust, built-in system tray support, and first-class builds for Windows (.msi/.exe), Linux (.deb/.AppImage), and macOS (.dmg). The Rust backend can directly call getifaddrs on Linux and GetAdaptersAddresses on Windows without shelling out.

4. Approach B: Native Per-Platform

Build separate native apps for each OS, sharing only the core business logic. Better performance and UX, but higher maintenance cost.

Windows: C# / WinUI 3

  • .NET 8 + WinUI 3 (Windows App SDK)
  • XAML UI with NavigationView sidebar
  • System tray via NotifyIcon
  • System.Diagnostics.Process for tshark
  • GetAdaptersAddresses via P/Invoke
  • MSIX packaging for Windows Store or sideload

Effort: ~3-4 weeks

Linux: GTK4 + Rust or Python

  • GTK4 with Adwaita for GNOME-native look
  • Rust (gtk4-rs) or Python (PyGObject)
  • App Indicator for system tray
  • /proc/net/dev for interface stats
  • Flatpak or .deb/.rpm packaging

Effort: ~3-4 weeks

5. Platform Porting Guide

5.1 Interface Discovery

macOS / Linux (POSIX)

// C / Rust / Swift — works on both macOS and Linux
struct ifaddrs *ifap;
getifaddrs(&ifap);
for (struct ifaddrs *ifa = ifap; ifa; ifa = ifa->ifa_next) {
    printf("Interface: %s\n", ifa->ifa_name);
}
freeifaddrs(ifap);

Windows (Win32 API)

// C# P/Invoke or Rust winapi crate
ULONG bufLen = 0;
GetAdaptersAddresses(AF_UNSPEC, 0, NULL, NULL, &bufLen);
PIP_ADAPTER_ADDRESSES addrs = malloc(bufLen);
GetAdaptersAddresses(AF_UNSPEC, 0, NULL, addrs, &bufLen);
for (PIP_ADAPTER_ADDRESSES a = addrs; a; a = a->Next) {
    wprintf(L"Interface: %s\n", a->FriendlyName);
}

Cross-Platform (Node.js / TypeScript for Tauri/Electron)

import os from 'os';
const interfaces = os.networkInterfaces();
for (const [name, addrs] of Object.entries(interfaces)) {
    console.log(`Interface: ${name}`, addrs);
}

5.3 tshark Integration

tshark is the same on all platforms. The only differences are the binary path and the interface naming convention. The capture file format (.pcapng) and command-line arguments are identical.

Rust Backend Skeleton (network.rs)

#[tauri::command]
pub fn discover_interfaces() -> Result<Vec<NetworkInterface>, String> {
    #[cfg(target_os = "macos")]
    { platform::macos::get_interfaces() }

    #[cfg(target_os = "linux")]
    { platform::linux::get_interfaces() }

    #[cfg(target_os = "windows")]
    { platform::windows::get_interfaces() }
}

#[tauri::command]
pub fn get_interface_stats() -> Result<Vec<InterfaceStats>, String> {
    #[cfg(target_os = "linux")]
    {
        // Read /proc/net/dev directly — no shell needed
        let contents = std::fs::read_to_string("/proc/net/dev")
            .map_err(|e| e.to_string())?;
        parse_proc_net_dev(&contents)
    }

    #[cfg(target_os = "windows")]
    {
        // Use WMI query
        query_wmi_network_stats()
    }

    #[cfg(target_os = "macos")]
    {
        // Shell out to netstat -ib
        parse_netstat_output()
    }
}

React Frontend Skeleton (App.tsx)

import { invoke } from '@tauri-apps/api/core';

function App() {
  const [tab, setTab] = useState('monitor');
  const [interfaces, setInterfaces] = useState([]);

  useEffect(() => {
    const poll = setInterval(async () => {
      const ifaces = await invoke('discover_interfaces');
      setInterfaces(ifaces);
    }, 2000);
    return () => clearInterval(poll);
  }, []);

  return (
    <div className="app">
      <Sidebar activeTab={tab} onTabChange={setTab} />
      <main>
        {tab === 'monitor' && <MonitorDashboard interfaces={interfaces} />}
        {tab === 'interfaces' && <InterfacesView interfaces={interfaces} />}
        {tab === 'capture' && <CaptureView />}
        {tab === 'patterns' && <PatternsView />}
        {tab === 'settings' && <SettingsView />}
      </main>
      <DebugPanel />
    </div>
  );
}

8. Platform Permissions & Privileges

Important: Packet capture requires elevated privileges on all platforms. This is the biggest deployment challenge.
PlatformRequirementSolution
macOS tshark needs access_bpf group or root Wireshark installer adds user to access_bpf; or run with sudo
Linux tshark needs cap_net_raw or root sudo setcap cap_net_raw+ep /usr/bin/dumpcap or add user to wireshark group
Windows Npcap driver must be installed Wireshark installer includes Npcap; or install separately from npcap.com

10. Recommended Next Steps

  1. Choose approach — Tauri is recommended for new builds; Python/Qt6 if you want to reuse v2.x code
  2. Set up Tauri project — npm create tauri-app@latest stealthshark-desktop
  3. Port business logic — Translate PatternRecognitionEngine and SessionManager to Rust commands
  4. Implement platform layer — Write platform/linux.rs and platform/windows.rs for interface discovery and stats
  5. Build React UI — Recreate the 6 views from the SwiftUI version using React components
  6. Test on each platform — Verify tshark integration, system tray, and file rotation
  7. Package — Use tauri build to generate .dmg (macOS), .msi (Windows), .AppImage/.deb (Linux)
